# QueueCat native extraction helper

## Windows x64 bundle setup

Unzip the Helper ZIP into a permanent folder. No separate 7-Zip, WinRAR, Rust, Python or system file-association change is needed. Open QueueCat Preferences, copy its Extension ID, then run `Install-QueueCat.cmd` from that folder and enter the ID. This registers only that extension for the current Windows user. Reload QueueCat only when its current queue is safely idle to grant the new nativeMessaging permission, then use Check Helper. Keep the bundled executable and engine folder in place. The installer can instead accept a trusted existing compatible `7z.exe` through `-SevenZipPath`; WinRAR is not a supported backend in this release.

The extension forgets completed extraction passwords and superseded retry passwords when no other pending/failed group needs them. If the helper is temporarily unavailable, deletion IDs are saved without passwords and retried with a five-minute backoff. Failed groups retain their encrypted password for explicit retry; removing a waiting/failed volume record cancels that extraction group and schedules its password for cleanup, while all downloaded files remain untouched. As a final retention limit, the helper expires DPAPI secret files seven days after their last write, based on file modification time; reading a secret does not extend its lifetime, and a future modification time is treated as expired. `ping`, `store-secret`, and `status` examine metadata for at most 128 eligible secrets per pass. Each pass enumerates and sorts eligible filenames to advance a locked, persistent cursor that wraps around, so fresh secrets do not permanently block later expired secrets; filename enumeration and sorting scale with the directory size and are not limited to 128 entries. Malformed cursor state safely restarts the scan. Cleanup runs only when the helper receives one of those requests; it is not a background timer and does not promise deletion while the helper is unused. A direct use of an expired secret returns `secret-expired` and removes that file. An expired password cannot be used for a later retry, so the user must enter it again. Uninstall retains residual encrypted state rather than recursively deleting user data.

Workers are admitted under a cross-process lock with a maximum of four live queued/extracting workers. Capacity-full requests remain pending in the extension with their original operation IDs. On Windows the host first asks the worker process to break away from a parent Job Object; if Windows returns `ERROR_ACCESS_DENIED`, it retries with the original detached/no-window flags. In that fallback case an enclosing browser job may still end the worker when the host exits, so persisted job state continues to detect and report a lost worker. Each list, test or extract child has a 30-minute limit and is attached to a Windows kill-on-close Job Object; timeouts terminate and reap it. Queue-lock waits expire after two hours with a visible failed state.

The helper registers as `com.queuecat.helper` and uses Chrome native messaging: every UTF-8 JSON request and response has a four-byte little-endian length prefix. A host process serves multiple frames until Chrome closes the pipe; messages over 1 MiB and unknown fields are rejected.

RPC v1 operations:

- `ping` → `{ok,version,sevenZipAvailable}`
- `store-secret {id,password}` → `{ok}`
- `start {id,paths,secretId}` → `{ok,status,outputDir?,errorCode?}`
- `status {id}` → job state
- `forget-secret {id}` → `{ok}`

IDs contain only ASCII letters, digits, `_`, and `-`, up to 128 bytes. Source paths must be absolute regular archive files in one directory. Supported split sets include `.7z.001`, `.zip.001`, `.part01.rar`, and legacy `.rar` + `.r00` sequences. A supplied split set must have one basename and contiguous volume numbers starting at one; paths are sorted before use. Job IDs cannot be reused for different paths, secrets, or source metadata. Windows DPAPI protects passwords at rest; job records never contain plaintext passwords. Windows file locks serialize workers and protect individual job state. The helper queues background workers and returns immediately.

Queued jobs record the worker PID while the parent still holds the job lock; the worker waits for that lock before changing state. A cross-process dispatch lock admits at most four live queued/extracting workers. A new request over capacity returns `worker-capacity` before creating job state; existing job IDs still return their current result even if the associated secret has since expired or been forgotten. Existing IDs still require the same secret ID, source paths, and unchanged metadata fingerprints for source files that remain present; a removed source does not hide an already recorded result. The serialized queue wait is capped at two hours and expires as `queue-timeout`. `status` uses the PID and lock to mark other orphaned queued/extracting jobs as `failed` with `worker-lost`. It never automatically retries an interrupted extraction. A missing state returns `job-not-found`; malformed or unreadable state returns `job-state-invalid` and is left untouched.

Before 7-Zip sees an archive, the helper stages only the explicitly supplied files into a unique sibling input folder, preserving their names. It uses hardlinks when possible and controlled copies otherwise. The helper validates archive entries, rejects traversal, absolute paths, ADS, reserved Windows names, and links, limits entry count and unpacked size, checks free space, and runs `7z t` before extraction. Each list, test, and extraction process has a 30-minute wall-clock deadline; timeout returns `engine-timeout`, terminates and reaps the child, and on Windows uses a kill-on-close Job Object for child-process cleanup. This prevents 7-Zip from discovering untracked neighboring volumes in the source directory. Extraction uses a new unique output folder, does not overwrite, retains the source archives, and never runs extracted files. These limits are defense in depth, not an OS sandbox; the 7-Zip parser runs with the user's account permissions. 7-Zip accepts passwords only through command arguments, so a password may be visible to same-user process inspection during extraction. The helper does not log commands or process output.

The engine is expected beside the helper at `engine/7z.exe`, or can be configured by the installer using the trusted `config.json` `sevenZipPath` field. The RPC cannot choose an executable. The installer requires explicit `ExtensionId` and `HelperExePath`, optionally accepts `SevenZipPath`, and registers only the exact extension origin under HKCU. It validates existing QueueCat-owned files before replacing them, backs up manifest/config while committing the registration, and restores prior files and the prior default registry value if a commit step fails; if rollback itself fails, it reports and preserves the backup directory. The uninstaller removes only the registration and manifest it owns; it leaves jobs, secrets, and extracted files alone.

Build and run focused tests from this directory:

```powershell
cargo test
cargo build --release
```

From the repository root, `native/tests/protocol-smoke.ps1` checks framed `ping` with isolated state under `artifacts/extraction-native`. `native/tests/archive-integration.ps1` accepts `-HelperExePath` and `-SevenZipPath` to check DPAPI secret handling, worker admission limits, encrypted extraction, volume isolation and incompleteness, retry idempotency, unique output folders, and immutable job inputs. `artifacts/extraction-native/installer-rollback-smoke.ps1` fault-injects the installer file/registration transaction using temporary files and a mock registry callback; it does not access the real registry. These scripts use fixtures only under `artifacts/extraction-native`; none registers a production host or touches real downloads.
