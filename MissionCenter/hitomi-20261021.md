# Hitomi 單本圖庫下載（2026-10-21，本機驗收）

使用者明確要求加入單本圖庫佇列下載；本輪只接受閱讀頁／單本頁，首頁、標籤、搜尋結果不展開。一本對應一筆 QueueItem，逐頁 WebP 存入獨立子資料夾；只在 Chrome 確認完成後前進頁碼，失敗重試保留已完成頁。

## 主要來源與按鈕確認

已以唯讀 HTTP 查驗官方公開 technical scripts，不下載使用者示例圖庫的圖片：

- https://ltn.gold-usergeneratedcontent.net/common.js：目前 CDN 網域、hash 對應路徑及 shard 計算。
- https://ltn.gold-usergeneratedcontent.net/gg.js：目前路由資料 m/s/b。b 是會變動的資料值，不能固定為查閱當下 timestamp。
- https://ltn.gold-usergeneratedcontent.net/reader.js：閱讀器 WebP 來源。
- https://ltn.gold-usergeneratedcontent.net/download.js：Download 按鈕逐張抓 WebP、以 JSZip 在分頁內產 ZIP Blob，並非一條可直接交給 Chrome 的整本 ZIP URL。

實作自行依公開資料格式撰寫；未複製 gallery-dl／GPL extractor 程式。遠端 JavaScript 只作嚴格資料解析，不 eval／載入執行。固定 metadata 端點、hash 路由、大小與 timeout 上限；不採用 metadata 中任意網址。

## 分工與邊界

Luna 一席負責原生 TypeScript 轉接層與安全測試，另一席負責既有 QueueEngine 的 gallery 分支與狀態回歸；主代理負責來源辨識、Chrome ports／manifest、UI、整合驗收。仍由背景協調器唯一寫入狀態；Katfile 下載流程與 Rust 解壓不重構。

Gemini 透過 Antigravity Bridge 完成 `src/shared/gallery-copy.ts` 的 28 組中英日文案。初次模型額度不足後，依本人要求查證即時模型目錄並沿用原 cascade、切換 `gemini-3.8-flash-medium`，沒有同檔第二位 writer。已收到 `QUEUECAT_GALLERY_COPY_REVISED`、`QUEUECAT_GALLERY_COPY_FINAL` 與 `QUEUECAT_GALLERY_COPY_SAFETY` 完成回執；修正手動重試、Chrome 核對、防重送、來源改版重新加入及本機測試版說明。背景通知和 UI 共用已知圖庫訊息映射，檔名與網站內容不當產品文字翻譯。

## 安全與可靠性修正

- Metadata 必須是指定圖庫 ID 的 JSON，最多 2,000 頁；固定來源、64 位 hash、動態路由資料、大小／timeout 上限。遠端資料不作程式碼執行。
- 圖庫標題不被逐頁檔名覆寫；本次 queue ID 決定獨立資料夾，重新加入不與舊圖片混冊。
- Chrome API 呼叫前保存下載意圖；只認領本外掛、相同 URL、相符時間的唯一下載。多個候選或交接資訊不完整時停止，重試不重送。
- 僅在 Chrome 確認完成後前進游標；每頁完成即持久保存，完成整本後釋放完整清單快照。
- 獨立可靠性審查找出「失敗圖庫 retry 搶占 active Katfile」與「安全移除阻塞後延遲續跑」；已修正為統一經 pump 排程，新增混合佇列回歸。圖片啟動入口也防守其他 active item，recheck 同樣經排程。
- UX 審查找出新增成功提示、缺漏錯誤翻譯與逐頁讀屏公告；已修復。交接不明說明保留「不會自動重送」，來源變更提示與實際安全移除操作一致。
- 圖庫不套用 Katfile 冷卻，也不送入 Rust 解壓；原 Katfile 和小幫手路徑保持原行為。

## 驗收進度

最終 `npm run check`、建置與 150 項測試已通過（17 個測試檔）。較繁忙時完整測試遇到 publish 子程序超過原 5 秒期限；該整合測試改為 30 秒上限，以 `npm test -- --maxWorkers=2` 重跑全數通過。損壞 ZIP 測試刻意產生的 tar 診斷不是產品失敗。

前期隔離樣本保存於 `artifacts/gallery-browser/2026-10-21T02-19-06-519Z/report.json`：一書一任務、三語 620px、真 Chrome 第二張最後一個 byte gate、暫停後當前完成且不送第三張、恢復、停止背景 worker 後不重抓皆有檢查。整合席後續發現 runner 的 hash.sort() 會錯配逐檔 hash 報告，因此舊 run 只能當集合／流程證據，不能當逐頁內容對應證明；已修為每個頁碼直接比對該頁 fixture bytes，最終新 run 另列。資料夾 regex 與未初始化報告欄位也是已修正的 runner 問題，不當產品缺陷。各次隔離 profile 與 loopback server 均清理；新 runner 即使 cleanup 發生錯誤也保證嘗試保存報告並回傳失敗。

CodeRabbit 本輪兩次：21 檔提出 3 issues（2 minor、1 major），確認後修正錯誤分類、通知 context 及交接不明的人工退出；10 檔修補複查 0 issues。沒有採用未知交接重新送出建議，而是本人確認後只移除紀錄並暫停整個佇列，不取消、不刪檔、不重送。原始 NDJSON 與範圍保存在 [證據資料夾](hitomi-acceptance-20261021/)。遵守每小時至多三次、每次至多 150 檔，沒有更新審查工具或上傳大圖／引擎／安裝包。

三席獨立評論已封存，另由獨立仲裁核對：未知頁數文字／ARIA 與逐頁 hash 配對為有效 P2，均修正；不中斷下載不輪詢 manifest 的行為保留，依仲裁明確限定為固定初始快照，重試／停在兩頁之間後重新排隊才核對變更。README 已釐清此契約，不宣稱即時改版偵測。未知頁數新增文案仍由 Gemini 作者提供（共 28 keys）；點擊交接不明的圖庫通知也改為開啟 Chrome 下載紀錄，來源圖庫與 Katfile focus 另有對比回歸。
